# オプション・設定値追加時の検証

この記録は追加時の検証結果。削除・値の縮小・名称/型/既定値の変更は、後続の[削除・変更の検証記録](reduction-verification.md)で確認している。

追加する項目の定義をテスト内で一時的に組み込み、解析・共通検証・診断への反映を確認した。製品のオプションや選択肢自体は増やしていない。

結論は、オプションの型・既定値・保存先・反復指定・選択肢・適用範囲は定義から反映される。ただし、定義の追加は機能の実装を代行しない。新しい制約や効果、既存選択肢の意味を増やす場合は、その検証・設定モデル・実行処理も更新する必要がある。

## 確認結果

| 追加・変更の試験 | 期待する動作 | 実際の結果 |
| --- | --- | --- |
| flag、整数、実数、文字列、Pathのオプションを追加 | コマンド前・階層途中・後で同じ型と値になる | 一致。オプション値の `plugin` や `doctor` はコマンドにならない |
| `choices` に新しい値を追加 | 新しい値を受理し、不正値では現在の選択肢を提示する | 一致。JSON `details.choices` に追加値も入る |
| 既定値5の整数を追加し、0・5を非対応コマンドへ明示指定 | 値が既定値でも `argument_error / option_scope` になる | 一致。値の不正より適用範囲違反を先に示す |
| `dest`、反復指定、`SUPPRESS` を追加 | 保存先・指定順序・未指定時の属性を維持する | 一致。単値の重複は最後を採用、反復は全件保持 |
| 未知の省略名、空の選択値、整数・実数の不正 | テキスト/JSONとも終了2、具体的で安全な `argument_error` | 一致。入力値は診断へ含めない |
| 値不足の後に `--help` | ヘルプより値不足の構文エラーを優先する | 一致 |
| 新しい競合を階層の前後に分ける | 値の検証より先に競合を示す。説明順序は固定 | 一致。競合グループの定義順で表示 |
| 複数の追加オプションの値を不正にする | 指定順序によらず定義順で診断する | 一致 |
| ヘルプ、`--`、別プロセスでの定義追加 | ヘルプに追加項目を反映、`--` 後は位置引数、初回importで共通検証にも反映 | 一致。別プロセスの試験ではOPTIONS以外の検証索引を手動更新していない |
| 手動Namespaceで追加オプションの独自dest・既定値を使う | 定義に従って適用範囲を判定する | 固定定義が残っていたため修正し、回帰テストで一致を確認 |
| 設定モデルに項目・別名・上下限を追加 | レイヤーの整理で削除されず、制約違反時に項目・条件・出典・位置を示す | 固定の診断項目一覧をモデル参照へ変更後、一致。`network.future_capacity must be greater than or equal to 1` 等を確認 |
| 既存設定項目のLiteralへ新しい値を追加 | 設定検証が追加値を受理する | 一致。処理の対応は別途必要 |
| 任意mappingのキーが既存モデル項目名と一致する | 利用者のキーを診断項目名として公開しない | 一致。`network.headers` で停止し、キーや値を含めない |
| 既存CLI選択肢だけを増やし、実行側を更新しない | 解析通過と機能対応を区別できる | 検査レベルは解析を通過してもレンダラーが拒否、画像形式は設定モデルが拒否。定義だけの追加では機能追加にならない |

引数不正・ヘルプの拡張試験では設定解決とコマンドハンドラーを禁止し、そこへ進んだら失敗するようにしている。設定試験は一時ファイルで行い、失敗時に書換えがないことも確認した。有効入力の試験は検証または単独の出力・設定処理までで、ダウンロード・プラグイン実行・Cookie操作・外部通信の成功を判定していない。

## 今回の修正

- 手動Namespaceのオプション判定は、固定の別名と値一覧ではなく、`OptionDefinition.attribute` と定義された既定値を参照する。
- 設定診断の項目名はPydanticモデルの構造から取得する。新しい項目・別名を別の許可一覧へ登録する必要がなくなり、利用者のmappingキーとの境界も明確になった。プラグインのダウンロード方針は対応するモデルを明示して診断する。
- レジストリの整合性テストは「35件」という固定件数を廃止し、一意性とパーサーに登録された項目との一致を確認する。
- 選択肢と消費側の契約を照合するテストを追加した。画像形式・既存ファイル処理・検査レベル・fallback・プラグイン検証・workflow範囲の定義を参照するため、未対応の値だけを追加した場合に不整合を検出できる。

手動Namespaceでは「既定値と同じ値を明示したか」は復元できない。通常のCLI解析結果では明示指定の記録があるため、既定値と同じ値でも適用範囲違反を検出する。
