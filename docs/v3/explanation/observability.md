# ログ・イベント・通知の解説

ログ、イベント、通知は、主結果を伝える経路ではありません。画像処理の成功・失敗は`DownloadResult`と`ImageOutcome`、操作全体の失敗は例外とCLIの終了コードで判断します。

画像単位の失敗では、取得・加工・保存の段階に対応する通知を一度だけ送ります。操作全体の失敗は、認証・設定・プラグイン・更新・保存・実行時の分類に分けます。`NotificationCategory`にあっても、`auth_login_success`やCookie・資格情報ストアへのアクセスのように、本体に明確な判定点がないイベントは自動発火しません。プラグインが認証要求を送っただけで、ログイン成功を装うことを防ぐためです。

イベントの受信処理、通知の配送、ログの出力先、Pythonログの収集の失敗によって、主処理の結果を隠しません。安全な診断警告を残して後始末を続けます。通常の診断やイベントの受信処理へ渡すURL・パス・例外は秘匿化の境界を通し、秘密情報を生のまま渡しません。

workflow専用記録には別の保存規則がある。対象ページの原文URLを`logs/workflow`の取得予定・逐次ログに残すため、
上記の通常診断ログの伏字規則とは区別する。予定保存失敗はその周回の取得を止めるが、逐次ログの失敗は
警告して取得を継続する。保存先・中断時の記録と制限は[ログリファレンス](../reference/logging.md#workflow-execution-files)を参照する。
